# Референсы — от чужого ролика к своему стилю

Читать на этапе 2 (стиль и дизайн-система), когда пользователь принёс образец «сделай как
тут», и режиссёру — перед выбором приёмов для акцентных битов. Выход — папка `refs/<имя>/`
проекта: листы кадров, замеры, `analysis.md`; поверх неё — гнёзда дизайн-системы
(`process/02-design.md`) и чек-лист правок.

## Техника из рефа, история своя

Из референса берём грамматику движения — тайминг, переходы, ритм, фактуру, — а сюжет, бренд,
персонажей и логотипы не берём. Идею пересказать чужую рекламу «как есть», только
с другими героями, пользователи отвергают. Для учебного ролика это тем более верно: содержание задано первоисточником, а у рефа
другой жанр и другой темп.

Что брать, назначается одним словом в задании:

- **МЕХАНИКА** (по умолчанию) — движение и тайминг приёма, вид — свой;
- **ПОДАЧА** — ритм, структура, порядок раскрытия, кадр в кадр не повторяется;
- **ТОЧНО** (повтор) — план, ритм и стиль по референсу, смысл свой; только по прямой просьбе
  пользователя.

## Как сохранить референс движения

Референс — образец движения, а не материал: видео и кадры чужой работы в ролик не вставляются, а в проекте лежит только
то, что агент может открыть снова. В `refs/<имя>/` сохраняется:

1. **Полоса кадров** вокруг ключевых моментов: 8–10 к/с, окно 2–3 с на каждый момент, кадры в ряд одной картинкой
   (шаг 3 процедуры ниже). Один обзорный лист на весь ролик (шаг 2) плюс по полосе на момент.
2. **Тайминг** — таблица в `analysis.md` (или `timing.json`): момент, длительность, кривая (затухающий выход, пружина,
   линейное), числа с пометкой `[M]` измерено или `[O]` замечено (шаг 4).
3. **Палитра** — hex и роль каждого цвета (фон, плашка, акцент, текст), из кадра удержания (шаг 4).
4. **Строка «что берём»** — одним словом механика / подача / точно и окно времени: «берём только X из окна t0–t1».
5. **Ссылка** — URL страницы или путь к файлу, дата просмотра и статус («просмотрено по полосе» или «только ссылка»);
   ссылка без просмотренных кадров референсом не считается.

Движение в своём ролике — число в `tokens.json`, а не пересказ референса (шаг 6). Свой ролик, сделанный по референсу,
сравнивается с ним теми же полосами кадров.

## Процедура «референс → стиль» в 8 шагов

Всё делает ffmpeg из `imageio_ffmpeg` (ffprobe на машине может не быть). Общая шапка команд
(bash, пути в двойных кавычках):

```
PY=python
FF=$("$PY" -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())")
R="refs/<имя>"          # папка разбора в проекте; ref.mp4 — копия образца
```

### Шаг 1. Паспорт файла

Длительность, кадровая частота, размер, есть ли звук — в шапку `analysis.md`. Немой файл — не
референс звука, так и пишется.

```
"$FF" -hide_banner -i "$R/ref.mp4" 2>&1 | grep -E "Duration|Stream"
```

### Шаг 2. Обзорный лист

Кадр раз в 2 с на весь ролик, сетка 5 × 4 (20 кадров на лист, лист покрывает 40 с). Подписи
времени не печатаем (`drawtext` на Windows требует путь к шрифту) — время клетки считается:
лист j, клетка k → `((j−1)·20 + k−1) · 2` с. Каждый лист открыть `Read`'ом; записать планы,
склейки, палитру на глаз и приёмы-кандидаты.

```
"$FF" -i "$R/ref.mp4" -vf "fps=1/2,scale=384:-1,tile=5x4" -vsync vfr "$R/overview-%02d.png"
```

### Шаг 3. Плотные серии на приёмах

Для каждого приёма из шага 2 — окно 2–3 с, 10 кадров в секунду (шаг 0,1 с); для
stop-motion-рефа — каждый исходный кадр окна, чтобы увидеть, держится ли рисунок 2 кадра.

```
"$FF" -ss 12.0 -t 2.4 -i "$R/ref.mp4" -vf "fps=10,scale=384:-1,tile=6x4" -frames:v 1 "$R/dense-12.0.png"
```

### Шаг 4. Замеры числами

Числа пишутся с меткой `[M]` (измерено) или `[O]` (замечено на кадре) — не смешивать.

- **Склейки** — моменты резкой смены кадра:
  `"$FF" -i "$R/ref.mp4" -vf "select='gt(scene,0.3)',showinfo" -f null - 2>&1 | grep -o "pts_time:[0-9.]*"`
- **Разность соседних кадров** (средняя яркость разности, 0–255) по всему ролику: быстрые
  отрезки, удержания, «на двойках» (ноль у каждого второго кадра):
  `"$FF" -i "$R/ref.mp4" -vf "tblend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=$R/diff.txt" -f null -`
- **Палитра** кадра удержания — 12 цветов, затем hex и роль каждого (фон, плашка, акцент, текст)
  читаются Pillow:
  `"$FF" -ss 8.0 -i "$R/ref.mp4" -frames:v 1 -vf "palettegen=max_colors=12" "$R/palette.png"`
- **Траектория ключевого объекта** — край или центр по кадрам плотной серии; отношение соседних
  шагов ≈ постоянно и меньше 1 — это затухающий выход (expo-out), равные шаги — линейное
  движение. Пример замера титула: 0,075 → 0,68 с шагом ×0,78.
- **Шрифты** — описать форму (гротеск или антиква, ширина, контраст) и подобрать 2–3 кандидата
  **с кириллицей**; не угадывать — лист вариантов на шаге 7.

### Шаг 5. `analysis.md` по полям dense

Открыть листы `Read`'ом (`Read "$R/overview-01.png"`, `Read "$R/dense-12.0.png"`) и записать
разбор по шаблону ниже. У каждого видео одна роль («берём отсюда только X») и окно времени.

### Шаг 6. Из разбора — стиль проекта

Переносимые правила без привязки к сюжету рефа раскладываются по гнёздам дизайн-системы
(`process/02-design.md`): токены, элементы, движение, звук, эталонные кадры, запреты.
Длительности, которые не мерили, пишутся как стартовые значения `[H]`, а не как замер.
Движение уходит числами в `tokens.json` → `motion`; что это включает в движке — отдельным
списком «implementation». Проверить, что токены читаются:

```
"$PY" engine/video/build.py demo --page
```

### Шаг 7. Проба листом до полного рендера

2–3 ключевых кадра в новом стиле — светлый, плотный текстом, переход — собрать страницей без
рендера и положить рядом с плотными листами рефа на одну картинку (Pillow: слева реф, справа мы);
варианты шрифта и палитры — листом с номерами (`process/02-design.md` «Выбор листами»).
Пользователь отвечает номером.

```
"$PY" engine/video/build.py <film> --only <sA>,<sB> --page
```

### Шаг 8. Чек-лист правок и честность

Из Must copy и «Материалов» — проверяемые пункты второго прохода: что сохранить из
утверждённого, что проверить в движении (обе стороны перехода, соседние кадры), что измерить,
чего не делать (передизайн при правке). Пункт, который меряется промером, становится условием
с порчей:

```
"$PY" engine/video/check.py <film> --page --red
```

В отчёте разбора — какие рефы реально просмотрены (лист, плотная серия, числа), что не
измерено, что выбрано, а не замерено. Ссылку без доступа к видео не считать просмотренной.

## Шаблон dense-разбора

Тот же набор полей режиссёр использует в раскадровке (`process/04-storyboard.md`).

```
# <имя референса> — разбор
Паспорт: W×H, fps, длительность, звук: музыка | голос | нет, речь: да | нет
Роль: что берём отсюда (одним словом: МЕХАНИКА | ПОДАЧА | ТОЧНО) и окно времени
## Brief        история · вид · палитра (hex → роль) · шрифты · правила движения · Never
## Objects      объект → форма, размер в долях кадра, где и когда виден
## Sequence     id | окно (с) | что происходит
## S01 · t0–t1 · заголовок
   Start: первый кадр в долях кадра
   Copy: экранный текст и речь
   Actions: «t0–t1 событие, числа» + [M] / [O] / [H]
   Relations: что едет с камерой, что чем обрезано, порядок слоёв
   End → next: последний кадр и как он переходит дальше
   Must-check: 4–6 проверяемых утверждений
## Must copy    5–8 пунктов
## Не брать     сюжет, бренд, персонажи, что противоречит жанру
## Маппинг      приём рефа → наш вид элемента или действие | «новый приём» → needs
## Unknowns     что не измерено и чем заменено
## Code map     сцена → id элементов → биты раскадровки
```

## Поправки при заимствовании приёма

- брать движение, а не вид: вид — только из нашей дизайн-системы, надписи по-русски;
- скорость ×1,6–2,0 к оригиналу, удержание после посадки — не короче времени чтения;
- ступенчатое движение и жёсткие склейки сглаживать: в чужих каталогах приёмов их большинство;
- поле Never разбора читать как список того, что ломает приём.

## Эталон пользователя

Свой эталон — принятый прошлый ролик, брендбук, образцы — скил заранее не знает: где он лежит,
спрашивается на интервью (В0, `process/00-intake.md`) и записывается в `links.md`. Из эталона берут
библию, раскадровку и стык пилота, сцены с приёмами, тематический плагин — как образец, не меняя его.
Нет эталона — опорой служат демо-сцены шаблона (`template/project/scenes/`).
