# Озвучка идёт через адаптер провайдера; оплата — с лимитом знаков в точке расхода

## Контекст

В прошлом ролике клиент MiniMax был вшит в конвейер; синтез тарифицируется по знакам, и повторные оплаты за ударения и числа были одним из классов ошибок. Нужны замена провайдера без правки ядра и оплата только с явным `--yes-i-pay`.

## Решение

Ядро озвучки знает только интерфейс `Provider`: `list_voices`, `synthesize`, `price_chars`, `cache_params`. Провайдеры лежат в `providers/<имя>.py`: `minimax` (реальный), `fake` (синус) и `replay` (готовые mp3). Демо и тесты идут через `replay` и `fake`.

Платный путь открывается только `--yes-i-pay --max-chars N`. Лимит обязателен, считает только некэшированные строки и списывается в `synthesize_paid(provider, line, voice_cfg, pay, budget)` — в точке расхода, а не в смете. Перед оплатой синтез отказывает при находках `speech_lint` без правки или разрешения. Кэш — по sha1 параметров (текст, голос, эмоция, скорость, питч и др.); усечённые записи отвергаются. Любое исключение печатается через `redact()`, который затирает значения всех переменных `.env`.

## Почему

Одного `--yes-i-pay` мало: флаг согласия без потолка не ограничивает сумму, поэтому `--max-chars` обязателен. Согласие и лимит в точке расхода защищают от разрыва между сметой и вызовом: набор некэшированных строк успевает измениться.

Отвергнуто:
- **Клиент MiniMax прямо в ядре.** Замена провайдера требует правки ядра.
- **Согласие только в смете.** Между подсчётом и вызовом может измениться кэш.
- **`--yes-i-pay` без лимита.** Нет потолка расхода.
- **Платный прогон при сборке шаблона.** Шаблон собран без платных вызовов: голоса демо — готовые mp3 (провайдер `replay`).

## Последствия

- Интерфейс спроектирован под одного реального провайдера. Второй реальный адаптер не писали, поэтому годность интерфейса для другого провайдера не доказана.
- Конфиг `voices.json` содержит поля, привязанные к провайдеру (`emotion_map`, `voice_env`, `provider_env`).
- Расход нельзя запустить «одной командой»: нужны оба флага и список строк, прошедших линт.
- Усечённый кэш отвергается, поэтому оборванный прогон дёшев: повтор доплачивает только за остаток.
