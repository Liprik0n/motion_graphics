# Скил — одна папка; агент видит его через ссылку или копию в каталоге скилов

## Контекст

Скил нужен любому проекту и должен храниться одной копией вместе с шаблоном (`template/`), процессом и проверками.

## Решение

Исходник — папка скила motion-studio в любом месте, где пользователь хранит свои материалы. Агент находит скилы в своём каталоге скилов (у Claude Code — ~/.claude/skills/). Туда ставится ссылка на папку скила: на Windows — junction (`mklink /J`), на других системах — символическая ссылка. Если загрузчик ссылку не видит — копия папки.

## Почему

Ссылка держит одну копию: правка скила сразу видна агенту. Junction на Windows не требует прав администратора, а загрузчик скилов проходит по нему как по обычной папке.

Отвергнуто:
- **Только копия в каталоге скилов.** Две копии, и правки скила нужно переносить руками.
- **Скил только в папке проекта.** Он перестаёт быть общим для следующих проектов.

## Последствия

- Видимость скила проверяют в новой сессии агента: скил есть в списке и загружается.
- Копия вместо ссылки — снимок: после правки исходника её обновляют заново.
- Ссылки внутри скила — относительные от его корня, поэтому папку можно переносить; пути к материалам пользователя живут в `links.md` (спрашиваются на интервью).
- Ссылку удаляют как ссылку (junction — `rmdir`, символическую — `rm` без рекурсии), не заходя внутрь: рекурсивное удаление через неё снесёт исходник.
