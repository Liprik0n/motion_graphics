# Конфиги проекта — единственный источник констант, без запасных чисел в коде

## Контекст

В прошлом ролике числа и пути жили в коде сборки и проверок, часть из них тематическая. Шаблон должен настраиваться под любую тему, не трогая движок.

## Решение

Все константы лежат в семи конфигах `template/project/`: `project.json`, `tokens.json`, `voices.json`, `speech_edits.json`, `music.json`, `sfx.json`, `rows.json`. Их читают и сборка, и проверка. Проверка не импортирует сборку и берёт ожидаемые значения из конфигов как из спецификации.

В коде нет абсолютных путей. Корень проекта один для всех точек входа: `--project`, затем `MOTION_PROJECT`, затем `<шаблон>/project`.

Обязательные ключи не имеют числового запаса в коде: при пропуске отказ «нет обязательного поля X». `canvas.px_per_in` ≠ 96 — тоже отказ. Числа по умолчанию (уровни 0,5 / 0,4 / 0,45 / 0,9, ducking ≥ 20 дБ, −16 LUFS и другие) живут значениями в поставляемых конфигах и записаны по замерам прошлого ролика.

## Почему

Запасное число в коде — второй источник константы рядом с конфигом, и пропущенное поле тихо превращается в чужое число. Отказ с именем поля заставляет сказать значение явно.

Отвергнуто:
- **Константы в коде проверки, как в прошлом ролике.** Шаблон нельзя перенастроить без правки проверки.
- **Запасные числа в коде на случай пропущенного ключа.** См. выше.
- **Один общий модуль констант, который импортируют и сборка, и проверка.** Проверка, считающая ответ тем же кодом, что и сборка, не находит ошибок.

## Последствия

- Опечатка в числе конфига проходит и сборку, и проверку: проверка ловит расхождение сборки с конфигом, но не сам неверный конфиг.
- Новый проект обязан заполнить все обязательные поля; пустой конфиг не работает.
- Имена полей и их набор — публичный контракт шаблона: переименование поля ломает все проекты, начатые от шаблона.
- Условия проверки не фиксируют число в тексте — их тестируют порчами конфигов.
