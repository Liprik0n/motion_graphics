# Шаблон проекта ролика — `template/`

Очищенный шаблон скила `motion-studio`: движок (`engine/`), конфиги и демо-фильм (`project/`)
без тематики прошлых роликов. Порядок работы, ворота и роли — в `../SKILL.md`; здесь — что где
лежит и какими командами всё запускается.

## Установка на машину — один раз

```
PY=<путь к python 3.10 или новее>
"$PY" "<скил>/tools/setup.py" check      что найдено (ядра, видеокарта, версии) и чего не хватает, с командой
"$PY" "<скил>/tools/setup.py" install    поставить недостающее; повторный запуск ничего не переустанавливает
"$PY" "<скил>/tools/check_skill.py"      зелёно ли: ссылки скила и тесты без браузера (--chrome — полный круг)
```

`install` ставит пакеты Python из `requirements.txt` скила (Pillow, imageio-ffmpeg — с ним приходит ffmpeg,
fontTools), набор Node из четырёх пакетов (`gsap`, `hyperframes` 0.9.x точной версией, `puppeteer-core`, `lottie-web` —
перечень и версии читаются из `engine/video/package.json` и `package-lock.json`) в общую папку `~/.motion-studio/node_modules` и Chrome в кэш
HyperFrames (`hyperframes browser ensure`). Общую папку переопределяет переменная `MOTION_NODE_MODULES`
(путь к её `node_modules`). Python и Node.js 22+ команда сама не ставит: называет их и чем поставить.
Проекты и сам шаблон подключают общую папку ссылкой — набор на машине один. Проекты, собранные раньше
на своём наборе (HyperFrames 0.8.x), остаются на нём: их ссылки установка не трогает.

Команде, которой не хватает программы или пакета, не нужна трассировка: `build.py`, `check_all.py`,
`new_project.py` и промеры называют недостающее и команду установки одной строкой (`engine/deps.py`).

Установку запускает заказчик заранее, до работы ролей: субагенту ставить пакеты не разрешают, а идёт она долго (в
пробе один пакет npm ставился 16 минут). Свой вызов npm в PowerShell — `npm.cmd`: `npm` упирается в политику скриптов;
`npm view` из Git Bash может висеть минутами.

## Новый проект с нуля

```
"$PY" "<скил>/template/new_project.py" "<папка нового проекта>" "Название ролика"
cd "<папка нового проекта>"
```

`new_project.py` копирует `engine/` и `project/`, подключает `node_modules` ссылкой (junction) на общую
установку (`--node-modules <путь>` — другой набор, `--copy-node-modules` — копия вместо ссылки), ставит в
`project/project.json` название и `"template_demo": false`. Из `project/` берётся только стартовый фильм
`demo` и его сцены; фильмы-фикстуры возможностей движка остаются в шаблоне (`--with-fixtures` — взять и их).
В непустую папку он отказывает и ничего не трогает; общей установки нет — называет команду, которая её
ставит. Дальше все команды — из папки проекта.

## Корень проекта и один `out`

Корень проекта — папка с `project.json` (в новом проекте — `<папка>/project`). Его находит одно
правило, общее для всех точек входа (`engine/project_root.py`):

```
--project DIR  (или --project=DIR)  →  переменная MOTION_PROJECT  →  <шаблон>/project
```

`build.py`, `check.py`, `storyboard.py`, `tts.py`, `speech_lint.py`, `check_audio.py`, `voice_gain.py`,
`music.py`, `sfx.py`, `check_mix.py` разбирают `--project` одинаково; флаг без папки или повторённый — отказ.
Все `paths.*` из `project.json` считаются от корня проекта: `paths.out` (`out`) — видео и звук фильма,
`paths.voices_out` (`out/tts`) — озвучка. Поэтому фильм на настоящей озвучке пишет
`"manifest": "out/tts/manifest.json"` вместо `replies` — и видео ставит каждую реплику по её
`scene_start` из манифеста (`tts.py --assemble`), а не подряд.

**Обязательные ключи без запасных чисел.** `project.json` (`fps`, `canvas.w/h/px_per_in`, `pause_sec`,
`scene_gap_sec`, `lead_sec`, `tail_sec`, `scene_exit_delay`, `frame.seam_half/seam_dur`, `paths.out`,
`paths.voices_out`, числа `voice_bars`) и `tokens.json` (`motion.*`, `density.*`, `type.<роль>.size_pt/weight`)
читаются без умолчаний в коде: нет ключа — отказ с именем поля. `voices.json voices.<id>.gain_db` — тоже
обязателен, читается одним местом (`engine/tts/voice_gain.py`) и сведением видео, и музыкой; голос фильма,
которого нет в `voices.json`, роняет сборку. `canvas.px_per_in` — только 96: страница (`stage.css`, разметка
сцен) свёрстана в px при 96 px на дюйм, другое значение сборка и проверка отвергают с объяснением.

Демо — две сцены (`demo-a`, `demo-b`), шов между ними, 4 реплики (готовые mp3, платного синтеза
не требует), около 22 с. Ещё два фильма-пробы: `styles` (сцена `style-probe` во всех стилях) и `kits`
(сцена `kit-probe` в шести мирах с набором сцены, с героем-манекеном на метках действий). И три фикстуры
возможностей движка: `bare` (сцены `bare-start`, `bare-timer` без каркаса: картинка-кадр, помехи, таймер),
`acts` и `acts-hide` (сцены `act-stage`, `act-sign`: часы, метки действий, камера, немая строка, тусклая вывеска,
ключ `hide`), `pen` (сцена `pen-probe`: буквы пером, набор букв, кадры-стопы) и `silent` (сцены `silent-a`, `silent-b`: ролик без голоса,
немые строки по тактам). Пробы и фикстуры живут в шаблоне и в новый проект не копируются: `new_project.py` берёт только
`demo`, а записи `project.json legibility_except` и `text_guard`, которые называют сцены фикстур, снимает сам
(ключи `wall_clock`, `fonts` и числа `tokens.json motion.*` остаются — они нужны и своему ролику, если он зовёт
эти плагины). Образцы полей смотри в шаблоне; проект со всеми фикстурами — `new_project.py … --with-fixtures`.
Когда появятся свои сцены, удали демо-сцены, `films/demo.json` и лист `demo` из `montage.json`.

Один и тот же проект, от пустой папки до `video-music.mp4`. Все команды без сети и без оплаты,
кроме явно помеченных.

| Возможности движка: фикстуры и их порчи (из шаблона или проекта `--with-fixtures`) | `"$PY" engine/video/build.py bare --page` и `check.py bare --page` / `--red` / `--samples` / `--red-slow`; то же для `acts` (и `acts-hide --page`) — `engine/video/CHECKS.md` «Возможности движка» |

Результат — `<папка>/project/out/demo/video-music.mp4`. Свой фильм: замени `demo` именем файла из `films/`.
Рендер сцены и пары сцен: `build.py <фильм> --only a,b` (и с `--page`); сцене, которой нужен кадр входа соседа, сосед
добавляется сам, и об этом пишется строка. У `build.py` есть `--estimate` (сборка без звука, длительности по смете — пока озвучки нет),
`--workers N|auto`, `--force` (мимо кэша). Черновик называется `video-draft.mp4`, а не `video.mp4`: `check.py` и `music.py --mux`
не должны принять его за финал. Размер и частота черновика, число воркеров и бюджет мс на кадр — в `project.json` блок `render`.

`timeline_offset_sec`, роли шрифтов, `wall_clock`), — `engine/video/plugins/README.md`.

Звук: `check_mix.py` (M1–M14: длины, ducking, −16 LUFS, −1 dBTP, голоса в пределах 0,5 дБ, эффекты
под речью и в паузах, лицензии треков), `check_audio.py` (reply = cache байт в байт, паузы,
протяжность, громкость голосов), `speech_lint.py` (цифры, кавычки, омографы, аббревиатуры встык,
слова носителя). У каждой проверки есть `--red` (порчи, каждая краснеет своей строкой) и
`--samples` (законные варианты, проходят молча).

## Глаз, полосы кадров, материалы, перо и Lottie

**Полоса кадров вместо своего скрипта.** `engine/tools/strip.py` — единственный способ добыть кадры сцены, шва или момента:
ряд кадров, лист с таймкодами, при `--video` короткий клип; страницу собирает сам, фильм не рендерит. Кадр с временем t —
кадр фильма в момент t при любой частоте полосы. Проверки V36 и V37 берут кадры у `strip.frames`, при первом запуске
`check.py --page` сам снимает полосу (около 13 с на демо под замком Chrome), дальше — из кэша `out/<фильм>/strips/_cache/`.
Исполнитель кладёт полосы в выход, режиссёр, QA и оркестратор открывают их же.

**Что V36 и V37 не видят.** V36 — слой, замерший с первого кадра, и сцену-слайд («нечего мерить»); сцена короче двух
`density.max_static` и шага промера (при шаблонных 6,0 с — короче 12,5 с) покраснеть не может вовсе: слой сначала движется
`max_static`, потом дольше него стоит. Такие сцены называет строка V36 («покраснеть не может: …»); если такова каждая сцена
фильма, `--red` даёт MISS «ни одна сцена не может покраснеть» и код 1. При шаблонном числе так во всех сценах `demo`, `bare`,
`acts` и `styles` — порча «слой заморожен» живёт на фильме `pen`; коротким сценам порог ставят своим числом
(`../profiles/card.md`). V37 мерит контраст в клетке, а не буквы: на пёстром фоне клетка может набрать контраст за счёт фона;
текст на canvas без `window.__textRects` не мерится совсем. Слипание слоёв обводки — только глазами по полосе.
Подробности и порчи — `engine/video/CHECKS.md`, раздел «Глаз».

**Материалы и растр.** Сложный предмет — картинкой или готовой анимацией, а не кодом (`../docs/adr/0010-rastr-i-gotovoe-ranshe-koda.md`).
`cutout.py` делает вырезку по маске фона, снимает ореол и добавляет запас поля; лист `--sheet` — на чёрном, белом и заданном фоне.
`--model` зовёт `hyperframes remove-background`: проверен на нарисованной фигуре человека (вырезана с мусором от фона), предметы режет
плохо — для предмета ровный фон и вырезка по цвету; настоящее фото не пробовали. Нужны `onnxruntime-node` 1.21.1 (отдельно:
`npm.cmd install onnxruntime-node@1.21.1 --save-exact` в общей папке, `npm ci` его уберёт) и веса ≈ 176 МБ (первый запуск).
`picture_check.py` отвечает,
что не так с принесённой картинкой и что попросить заново. Каждый файл в `project/assets/` обязан иметь строку в
`project/materials.json` (`file`, `source`, `license`, `author`, `url`, `note`); разрешённые лицензии и запрещённые перечисляет
`../catalog/sources.md`.

**Перо, Lottie, набор букв.** Буквы пером — метка `act` с `do: "write"` и движениями `pen_stem` или `pen_wire` (числа — `tokens.json`
`motion.act`); `plugins/pen.js` подключается сам. Готовая анимация — элемент раскадровки `kind: "lottie"` (`src`, `at`, `speed`, `loop`),
файл лежит в проекте, по сети ничего не грузится; проигрыватель — пакет `lottie-web` 5.12.2 из набора Node движка
(`engine/video/package.json`), испытан на файле из фигур `libs/pulse.lottie.json`. Набор букв открытки (`libs/card-kit.js`) подключается ключом фильма
`"libs": ["card-kit"]` и сам отдаёт V37 области строк фразы после сборки (`L.textRects`); окна и нырок в браузере не запускались.

**Ролик без голоса.** Профиль `../profiles/card.md`: `music.json "without_voice": true`, немые строки шкалы `{silent: true}` по тактам
музыки, сцена без единой реплики законна; эффекты ставятся от действий сцены (`sfx.json`, `kind: act` и `kind: mark`). Демо — фильм `silent`.

**Шрифты стилей — файлы.** Шрифт заголовка и надписей каждого стиля лежит в `engine/video/assets/fonts/` под лицензией OFL с
кириллицей (таблица «семейство → файл → источник» — `engine/video/assets/fonts/README.md`); системные шрифты Windows стили не зовут.

## Стили

Стиль — целый мир кадра (фон, предметы, шрифт заголовка, движение, звук) поверх фирменного текста; 14 готовых
лежат папками в `engine/video/styles/`, свой стиль проекта — папкой `project/styles/<имя>/`. Шесть из них
(`flat-edu`, `pixel`, `comic`, `paper-cut`, `neon-line`, `tv-splash`) дают сцене ещё и набор — инструменты, которыми
разметка сцены рисует свой мир и своего героя (`engine/video/styles/README.md` «Миры с набором сцены»; проба —
`build.py kits`). Героев и надписей в коде стилей нет: они — данные проекта. Какой брать для
какого ролика — `../catalog/styles.md`; как устроен стиль и как сделать новый — `engine/video/styles/README.md`.

**Включить.** Сильнейший первым: на сцену — `"style": "<имя>"` в `scenes/<сцена>/storyboard.json`
(`null` — без стиля); на один проход — `build.py <фильм> --style <имя>` (проход ложится в `out/<фильм>/<имя>/`);
на фильм — `"style"` в `films/<фильм>.json` (`"styles": [...]` — несколько проходов сразу); на проект —
`"style"` в `project.json`. Предметам мира режиссёр оставляет место: `"decor_zones"` в раскадровке сцены.

**Проверить на своём фильме, а не только на пробе.** Мир стиля сам кладёт светлое окно цветом `--c-paper`
под каждую зону текста сцены (`StyleCore.textWindows`), поэтому подписи читаются на любой раскладке —
и это проверяется на настоящем фильме:

```
"$PY" engine/video/build.py demo --page --style glass        проход в стиле: страница, промер DOM, промер стиля
"$PY" engine/video/check.py demo --page --style glass        V1–V43 прохода (то же: check.py demo/glass --page)
"$PY" engine/video/check.py demo --page --style glass --red  порчи «стиль на фильме роняет контраст подписи»
"$PY" engine/video/check.py demo --page --style glass --samples
"$PY" engine/video/build.py styles --page && "$PY" engine/video/check.py styles --page   все стили на сцене-пробе
```

Условия стиля: V21 — текст читается (контраст строки ≥ `legibility.contrast_min` или ≥ 95 % бренда), V22 —
цвета и шрифты узлов только из бренда и `decor` стиля, V23 — вспышки не чаще порога, V24 — кадр детерминирован.
Без `--style` команда `check.py demo` проверяет фильм без стиля; неизвестный проход — отказ с подсказкой.

**`style_brand_lock`.** `project.json "style_brand_lock": true` — замок бренда, «только фактура»: мира нет
(ни фона, ни предметов, ни шрифта заголовка, `world.css` не кладётся), стиль даёт лишь фактуру поверх
фирменного фона, V22 строгий. Для заказчика, чей бренд-бук не допускает чужой мир.

**Время.** Промер стиля (`--page`) снимает каждый кадр в 1/10: ≈ 1–3 мин на 22 с демо-фильма на проход, 14
стилей — до получаса. Проходы идут по одному: безголовый Chrome на машине один (замок ниже). Рендер mp4 на секунду ролика: без стиля ≈ 4 с, скетчбук
≈ 7, плёнка ≈ 11 с и пик временных кадров ≈ 1,2 ГБ на 12 с (зерно не сжимается в PNG) — длинный фильм в тяжёлом
стиле рендерить с `--chunk-sec 10`.

## Кусок рендера, склейка, замок браузера, общий прогон

**Кэш по сцене.** Кадры лежат по сценам: `out/<фильм>/frames/<сцена>/frame_%06d.png`, отметка сцены — `frames/<сцена>/stamp.json`
(отпечаток самой сцены и её соседей по шву). Правка одной сцены перерендеривает её и тех, кого она задела на шве; остальные
берутся из кэша, `--force` — мимо кэша. Черновик кладёт кадры в `frames-draft/<сцена>/`. Считать кадры — через `stamp.frame_files` и
`stamp.frame_counts`, не глобом по плоской папке. Зависимость сцены от чужой сцены вне окна шва кэш видит только по явной ссылке:
перед сдачей — рендер с `--force`. Ролик длиннее пары минут по-прежнему можно делить на фильмы-куски (`build.py <фильм> --png` →
`frames/` и отметка `frames/stamp.json`), если склейка нужна из нескольких фильмов.

**Пересборка страницы кадры не удаляет.** `build.py --page` и общий прогон проверок пересобирают страницы; если страница собралась
той же, отметка совпала и кадры годятся. Страница изменилась — кадры остаются на диске, но сборка пишет «кадры устарели», а склейка
такой кусок не берёт и называет команду перерендера.

**Журнал и бюджет.** В `out/<фильм>/render.log` на каждую сцену строка «сцена <id>: N кадров, X мс/кадр»; при превышении
`render.frame_budget_ms` (в шаблоне 300) — строка `ТРЕВОГА`. Тревога — повод упростить сцену: вынести размытия и тени в картинку.

**Склейка.** `project/montage.json` — монтажный лист: имя листа → куски по порядку (`{"film": …}`, готовая
PNG-последовательность `{"frames": …}`, готовый `{"mp4": …}`). `assemble.py <лист> --check` проверяет всё до
кодирования (кадры, отметки, число кадров, длину звука), без `--check` кодирует один mp4 одним проходом — сшивка
готовых mp4 рвёт GOP на стыке. Звук: поле `audio` листа (один сведённый файл на всю склейку) либо `mix.m4a` каждого
куска (`engine/audio/music.py <фильм>`); длина звука обязана совпасть с кадрами ± 1 кадр, молча ничего не подгоняется.
Музыку, которая идёт через несколько кусков, сводит проект одним файлом и отдаёт склейке полем `audio`.

**Замок браузера.** Безголовый Chrome на машине один: два разом вешали машину. Сборка (промеры, рендер), порчи
проверок и общий прогон берут замок `engine/chrome_lock.py` сами — папка во временной папке системы, одна на все
проекты (`MOTION_CHROME_LOCK` — другое место). Свой скрипт с браузером (лист кадров, снимок страницы) запускается
только так: `"$PY" engine/tools/with_chrome_lock.py [--timeout СЕК] <команда>`. Второй запуск ждёт первого; замок
умершего процесса снимается сам. Ожидание ограничено: час по умолчанию, свой предел — переменная
`MOTION_CHROME_LOCK_TIMEOUT` (секунды) или `--timeout`. Не дождавшись, `build.py`, `check_all.py` и
`with_chrome_lock.py` выходят одной строкой: кто держит замок (pid, метка, с какого времени) и где его папка.

**Общий прогон.** `"$PY" engine/tools/check_all.py` строит шаги из проекта: свои тесты проекта, каждый фильм из
`films/` (сборка `--page` и проверка; порчи — у фильма, для которого они калиброваны), сухой прогон каждого листа
склейки, линт текста, промер голоса и микса, если они есть, и свои шаги проекта — `project.json "check_all":
[{"name", "cmd": ["<скрипт от корня проекта>", …], "needs": […], "slow": bool, "chrome": bool}]` (порчи сцен лежат
рядом со сценой и подключаются сюда; `"chrome": true` — шаг сам запускает браузер). Чего нет на чистой машине —
`SKIP` с причиной. `--quick` — без медленного, `--full` — ещё порчи стилей, `--films a,b`, `--list`.

Тест регистрируется сам: любой `test_*.py` под корнем проекта находится обходом (папки `out`, `node_modules` и
скрытые — мимо). Тест, которому нужен браузер, объявляет в файле строку `NEEDS_CHROME = True` — он идёт под
замком и не входит в `--quick`. Замок Chrome прогон берёт только на шагах с браузером (сборка страницы,
медленные порчи, такие тесты), а не на весь прогон. Самотесты движка и фильмы-фикстуры шаблона в прогон проекта
не входят — их гоняет `"<скил>/tools/check_skill.py"`; тому, кто правит движок в своей копии, — `check_all.py --engine`.

## Известные обходы платформы

- **ffprobe.** HyperFrames требует его при запуске, а в системе его может не быть. `engine/video/tools/ffprobe.exe` —
  заглушка: композиция немая (png-sequence), звук сводит ffmpeg из `imageio_ffmpeg`, а заглушка громко
  отказывает, если её всё же позовут. Нет `ffprobe.exe` — `build.py` соберёт его из `ffprobe_stub.cs`
  встроенным в Windows `csc.exe`.
- **Шрифт.** Chrome молча отвергает файл с кривым каталогом таблиц и рисует запасным шрифтом.
  Свой шрифт перед подключением в `tokens.json` (`fonts`) пропусти через
  `"$PY" engine/video/tools/fix_font.py <исходный.ttf> <выход.ttf> [--cp1251]` (пересчёт полей, коды «Ё», «ё», «№»);
  промер `probe.json → fonts` обязан дать `loaded`. Фирменного шрифта в шаблоне нет — демо
  идёт на Liberation Sans Narrow (не OFL: Liberation Fonts license — GNU GPL v2 с исключением для шрифтов; текст —
  `engine/video/assets/fonts/LICENSE-LiberationSansNarrow.txt`).
- **Папка `out` проекта.** `build.py` пишет `schema.json` и `cache/` в `<проект>/out` даже при `--out-dir`;
  порчи и пересборки для проверки гоняй на копии проекта. `out/` шаблона в поставку не входит.
  `--out-dir` можно давать относительным: он приводится к абсолютному от текущей папки.
- **`node_modules` — ссылка.** Удаляя проект целиком, ссылку снимай как ссылку
  (`cmd /c rmdir "<проект>\engine\video\node_modules"`), а не рекурсивным удалением: иначе удалишь
  общий набор — он один на все проекты машины.
- **Кириллица в консоли.** Код пиши в файл и запускай, не передавай длинной строкой через `python -c`;
  в каждом скрипте `sys.stdout.reconfigure(encoding='utf-8')`. Пути с русскими буквами и пробелами — в кавычках.
- **Ключи.** Значения `.env` не печатаются нигде: ни в коде, ни в логах; `redact()` затирает их в любом выводе.
  Ошибка `access to this voice_id` — сначала `tts.py --voices` (бесплатно), потом синтез.

## HyperFrames 0.9.x: что изменилось против 0.8.181 и чем это обходится

Замеры скорости этой машины (12 ядер 2013 года, без видеокарты, во время замеров занята) и решение об оставлении движка — `../docs/adr/0009-dvizhok-ostayotsya-hyperframes.md`;
про железо и аренду — `../docs/hardware.md`. Кратко: демо 1920×1080, 647 кадров, было 91 мс/кадр на 3 воркерах, стало 60–74 мс на 8; черновик 960×540
при 15 к/с — 40 мс/кадр, в 2,6 раза быстрее финала (цель «втрое» не достигнута: ≈ 15 с постоянных на каждый вызов HyperFrames).
Проба 2026-11-22 против целей заказчика: черновик сцены 8,73 с — 114,4 с при цели ≤ 2 мин, выполнена; полный ролик 43,63 с
(1309 кадров 1080×1920, копия открытки на её движке, 8 воркеров) — 12,9 мин при 590 мс/кадр в почти тихом замере и 16,6 мин
при 760 мс/кадр под нагрузкой при цели ≤ 10 мин, не выполнена (до настройки — 19 мин). Замер рендера — отдельный шаг на
тихой машине: оба полных замера шли с соседями, разница между ними 3,7 мин.

Шаблон собран и проверен на HyperFrames 0.9.20 (версия закреплена в `engine/video/package.json`); прежние
проекты остаются на своём 0.8.181. Сверка 2026-11-22 на этой машине, демо шаблона: страница, проверка, порчи,
образцы зелёные; первые 150 кадров демо на 0.8.181 и на 0.9.20 совпали попиксельно; время кадра то же
(≈ 0,15 с на кадр в три воркера); число кадров полного рендера равно расчёту `frame_count()`.

| Что изменилось | Чем грозит | Обход |
|---|---|---|
| У рендера появилась своя очередь: по справке `render --help`, он ждёт, пока идёт другой рендер того же пользователя (`--wait` включён по умолчанию) | рендер молча стоит, если рядом кто-то рендерит HyperFrames мимо движка | движок и так держит один Chrome своим замком с пределом ожидания; очередь HyperFrames отключает `HYPERFRAMES_RENDER_LOCK=off`, отказ вместо ожидания — `--no-wait` |
| Новые ключи рендера: `--start`, `--end`, `--max-bitrate`, `--buffer-size`, `--keyframe-interval`, `--page-motion-blur`, `--prores-profile`; новые команды `measure`, `diff`, `reverse`, `templates`, `update`, `billing` | ничем: прежние ключи не убраны | движок их пока не зовёт |
| npm 12 не запускает установочные скрипты пакетов и предупреждает об `esbuild` | предупреждение при `setup.py install` | ничего не делать: рендеру этот скрипт не нужен |

Не изменилось: требование Node.js 22+, сборка Chrome в кэше (промеры и проверки страницы от версии HyperFrames
не зависят — они идут через `puppeteer-core`), ключи, которыми движок зовёт рендер (`render <папка> -c <страница>
--format png-sequence --workers N -o <папка>`), переменные (`HYPERFRAMES_FFMPEG_PATH`, `HYPERFRAMES_FFPROBE_PATH`,
отказ от телеметрии и самообновления), заглушка ffprobe, выбор захвата (`--browser-gpu` — авто, `--no-browser-gpu` — программный; на машине с
видеокартой не проверено). Несовместимого с прежним поведением движка сверка не нашла.
